# MVP 범위와 다음 단계

## 현재 구현

CSV Collector → 엄격한 입력 검증 → 가중치 평가 → 플랫폼별 오프라인 템플릿 → SQLite → Streamlit 검토 → 수동 다운로드.

- Python 표준 라이브러리 기반 도메인/CLI, 선택 의존성 Streamlit.
- 키워드+플랫폼으로 안정적인 ID를 만들고 재입력 시 덮어쓰지 않습니다.
- import와 상태 변경은 트랜잭션, 수정은 revision 기반 낙관적 잠금으로 보호합니다.
- 본문과 출처·측정 메타데이터는 JSON payload로 함께 보관하고 변경 이벤트를 기록합니다.
- 샘플 데이터에는 조사한 것처럼 보이는 출처 URL/발행일을 만들어 넣지 않습니다.
- 공개 배포, API 호출, 자동 조사, LLM 생성, 실제 예약/발행은 이번 MVP 범위에 포함하지 않습니다.
- API 호출 한도 0회, 비용 상한 $0, 예상 비용 $0, 재시도 0회로 외부 호출 자체가 없습니다.
- 자동 알림 전송은 없습니다. 실패는 CLI의 비정상 종료/대시보드 오류 및 GitHub Actions 실패로 알립니다.

## 지속 저장소

로컬 개발은 SQLite, 비공개 Codespace도 개발 환경으로만 사용합니다.
배포 전 관리형 PostgreSQL로 Repository를 구현하고 스키마 마이그레이션을 도입합니다.

권장 테이블:
- keywords / metric_observations: 관측 시점·공급자·단위·실측/추정 구분.
- drafts / draft_versions: 주제, 플랫폼, 본문, 버전, 상태, 예약일.
- sources / claim_sources: URL, 발행일 nullable, 조회일, 주장별 연결, 확인 여부.
- review_events: 인증 사용자, 검토 대상 원고 hash, 승인/반려, 시각.
- generation_jobs: idempotency key, 상태, 임대 만료, 시도 횟수.
- usage_reservations: 공급자, 날짜, 예상 토큰/비용, 실제 사용량, 상한 예약.

생성 작업은 (주제, 플랫폼, 템플릿 버전, 요청 날짜) 고유키를 사용하되,
기존 승인 원고를 자동 교체하지 않고 새 버전을 검토 대기시킵니다.
일일 수집은 GitHub Actions가 실행하고 모든 상태/결과를 PostgreSQL에 저장해야 합니다.
Actions runner, cache, artifact는 운영 원고의 원본 저장소가 될 수 없습니다.
별도 암호화 백업과 복원 테스트, DB TLS, 최소 권한 계정을 적용합니다.
이 설계의 실제 연결·마이그레이션 검증 전에는 운영 예약 생성 workflow를 켜지 않습니다.

## PR 중심 콘텐츠 승인 설계

AGENTS.md의 우선 방향에 따라 다음 단계에서는 원고별 Markdown+메타데이터를
별도 콘텐츠 브랜치의 PR로 제안합니다. 현재 PR은 애플리케이션 코드 제안입니다.

1. DB 원고 버전과 본문 hash를 PR 메타데이터에 연결합니다.
2. 허용된 검토자의 승인과 모든 검증 체크를 확인합니다.
3. 승인 이벤트를 DB에 저장하되 승인 대상 hash가 현재 버전과 다르면 무효화합니다.
4. PR의 승인/병합만으로 외부 발행하지 않습니다. 승인된 수동 발행 패키지를 제공합니다.

MVP 대시보드 승인 이벤트는 로컬 기록입니다. GitHub 승인 이벤트 동기화는 미구현입니다.

## API 단계별 연결 (MVP에서는 비활성)

1. **네이버 검색광고**: 공식 문서·이용 약관·인증/쿼터 확인 후 adapter와 fixture 테스트.
   월 PC/모바일 검색량, 경쟁 지표의 단위와 관측일을 보존합니다.
   '<10' 같은 구간값을 정확한 정수로 단정하지 않습니다.
   광고주 입찰단가를 블로그 게시자의 수익으로 해석하지 않습니다.
2. **네이버 데이터랩**: 공식 상대 추세 지수의 요청 기간/그룹/정규화 기준을 저장합니다.
   검색광고의 실제 월 검색량과 별도 열로 다룹니다.
3. **자료 조사**: 허용된 공식 출처 중심으로 주장별 근거를 수집합니다.
   발행일 미상은 null, 웹 문서는 신뢰할 수 없는 입력으로 처리합니다.
   조회 실패를 샘플 성공으로 숨기지 않고 검토 필요로 기록합니다.
4. **OpenAI**: 사용자 확인 후 연결합니다. 검증 자료만 프롬프트에 전달하고
   플랫폼별 구조를 분리해 JSON schema로 응답을 검증합니다.
   미확인 주장/출처 없는 수치를 거절하고 검토 목록에 남깁니다.
5. **인증/배포**: OIDC 로그인, 허용 사용자 목록, 서버 측 권한 검증, HTTPS,
   PostgreSQL을 먼저 연결하고 배포 차단을 해제합니다.
6. **운영 예약 실행**: 매일 한국 시간 오전 8시(UTC 23시)에 수집/생성을 실행할 수 있도록 구성합니다.
   생성 결과는 DB에 남고 사람의 승인을 기다립니다. 공식 지원 여부와 무관하게 이번 요청에는 자동 발행을 추가하지 않습니다.

키는 로컬 Git 미추적 환경 변수, 배포 secret manager, GitHub Actions에서는
GitHub Secrets에서만 읽습니다. API 키·DB URL·본문 전체를 로그에 출력하지 않습니다.
현재 코드는 예시 키가 있어도 읽거나 호출하지 않습니다.

## 비용·호출 제한 설계

미래 API adapter는 작업 전에 DB 트랜잭션으로 일일 호출 수/비용을 예약합니다.
최대 입력·출력 토큰과 운영자가 지정한 모델 단가로 상한을 계산하고 한도 초과 시 호출하지 않습니다.
응답 사용량으로 정산하고, 결과 불명인 타임아웃은 비용 예약을 보수적으로 유지합니다.
요청당 재시도 최대 2회(총 3회), 429·일시적 5xx에 한정해 backoff와 jitter를 적용합니다.
401/403·잘못된 요청은 즉시 실패합니다. 재시도도 비용/호출 예산에 포함합니다.
프로세스 재시작이나 병렬 작업이 한도를 우회하지 못하도록 공유 DB에서 계산합니다.
UI에는 공급자별 사용량/상한/예상비용/추정 단가 기준일을 표시합니다.

## 운영 검증 기준

API fixtures, DB 동시성/재시작, 비용 초과 및 타임아웃, OIDC 미인증 차단,
승인 후 본문 변경 시 무효화, 백업 복원을 통과한 뒤 배포합니다.
기기 테스트는 갤럭시 태블릿 세로/가로 화면에서 업로드·본문 수정·다운로드를 확인합니다.
